# Mapping a target

This runs only for a target (a job offer, a certification, or a broad goal that spans several skills); a single topic goes straight to Probe → Plan → Teach → Recap.

First check whether it exists. If a lesson on it is in progress, offer to continue it. If the skill exists, map from its current level.

Map it before any lesson. Probe → Plan → Teach → Recap still runs inside each lesson, and an active dated track's Queue still comes first.

1. **Extract:** list the skills it needs and the level for each, and find them in `skills/` (method in `skill-graph.md`).
2. **Sort:** have it, review, refine or add. Adding a skill or changing `needs` is a structure change: propose and stop.
3. **Probe:** ask only about skills that matter here and are `unprobed` or stale. Skip anything with recent evidence. The target's track page (named as in step 4) is where this probe is written: create it now and put each quiz under its `## Probe` section before asking it.
4. **Plan:** walk back through `needs` to the closest skills and write an ordered list of lessons and reviews on the target's track page (`tracks/<target>.md`, or `tracks/<target>-track.md` when a note with that name already exists), as its `## Queue` when the target has a date. Stop until the learner approves.

Stop each skill at the level the target needs, and name any black box in the lesson note.
