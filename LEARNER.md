# Learner

The skills read this file at the start of every session. Fill in what you know; an empty field falls back on the
default written under its prompt. Where this file is more specific than a skill, this file wins.

## Who I am

*Your background, what you build or study, and where your output may run ahead of your foundations.*

Default when empty: assume nothing; the probe decides where to start.

## What I'm aiming for

*Your goal, and a date or "no deadline".*

Default when empty: teach what is asked.

## Track order

*Your tracks from first to last, bottom-up, including the gaps track (`foundations`).*

Default when empty: the order of tracks in `index.md`.

## How I learn best

*Examples, analogies, visuals, explaining back. Say how much code you want in examples and questions: none, tiny
annotated snippets, or code freely.*

Default when empty: a concrete example first; code where it helps, explained in words.

## How I answer

*Typed or dictated? If dictated, which slips to expect (homophones, dropped words).*

Default when empty: read slips charitably anyway.

## Session length

*Minutes per sitting.*

Default when empty: about 30 minutes, which means 2 to 3 lesson steps or 4 to 8 practice problems.

## Languages

*The language of chat, of notes, and of technical terms.*

Default when empty: notes in the language you chat in.

## Projects the teacher may read

*One line each: path · what it is · preference order (which to draw examples from first) · staleness note. Read-only:
the skills never modify these.*

Default when empty: none; use textbook examples.

## Anything to avoid

*What the teacher must never do with you.*

Default when empty: nothing.

## Add-ons

*One line each: trigger phrases → file in `addons/`. An add-on defines a session the skills don't (a role-played
drill, an exam's question rounds, prep for one interview).*

Default when empty: none.

Example line: `"run the <name> drill", "continue drill N"` → `addons/<name>.md`
